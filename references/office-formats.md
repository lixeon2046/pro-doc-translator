# Office 格式与其他文本格式的原位翻译

原则：**在原文件副本上原位替换文本**，最大限度保留样式、版式与对象。绝不从头重建版式。

## DOCX

1. 复制原文件为工作副本，`python-docx` 打开。
2. 遍历 `document.paragraphs` 与所有 `table` 单元格、页眉页脚、文本框（`document.shapes`）。
3. 翻译单元 = **run**（保留每个 run 的样式）。相邻同样式 run 先合并再翻译，避免句子被切碎导致译不一致。
4. ⚠️ run 长度变化是常态：中文通常比英文短 20–40%，表格行高自适应即可；避免手工改 `w:sz`。
5. 术语强制：译文写入前过一遍词汇表正则替换校验。
6. 交叉引用/域代码/书签文本不译。

## XLSX

1. `openpyxl` 打开副本；遍历所有 sheet 的单元格、共享字符串。
2. 只译文本单元格；公式（以 `=` 开头）不动；数字/日期格式不动。
3. 单元格长度增长时：对齐换行开关 `alignment.wrap_text = True`，列宽适度加宽（×1.2 封顶）。
4. 图表标题/数据标签如有文本层一并翻译。

## PPTX

1. `python-pptx` 遍历所有 slide 的 shapes：文本框架、表格、SmartArt（XML 级）、备注。
2. 翻译单元 = paragraph（跨 run 合并后翻译，写回首个 run、清空其余）。
3. ⚠️ 文本框溢出风险：中文更短通常安全；英文→中文更长则检查 `word_wrap` 与 shape 高度，必要时字号 −1~−2pt。
4. 母版/版式占位符提示文本不译。

## Markdown / HTML / 纯文本

- 直接分块走翻译流水线；Markdown 保留代码块/行内代码/链接 URL/锚点不译，frontmatter 按用户指令
- HTML 用 BeautifulSoup 只替换文本节点，标签属性（alt/title 可选译）与结构不动

## Office 格式 QA

- 回读校验：文件可正常打开、段落数/表格数/页数与原文档一致
- 术语一致性扫描（同 PDF 的 glossary_drift 逻辑）
- 残留源语言扫描（白名单：代码/公式/品牌）
- 抽样渲染：DOCX/XLSX/PPTX 转 PDF 后（`soffice --headless --convert-to pdf` 或用户环境等效工具）走视觉验收

## 通用纪律

- 原文件只读，一切改动在工作副本上
- 翻译单元的合并/拆分只影响文本内容，不触碰样式节点
- 每种格式先在 1–2 页样本上试翻并渲染确认，再全量执行
