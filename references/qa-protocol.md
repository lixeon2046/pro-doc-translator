# QA 协议与视觉验收闭环

两层：**构建前译文 QA**（翻译流水线出口）与**构建后成品 QA**（PDF/Office 出口）。全部归零才进入视觉验收。

## 一、译文 QA（每分块出口 + 全量合并后）

`scripts/validate_trans.py <workdir>`：
- id 一一对应（missing/extra 必须为空集）
- JSON 合法；null 仅限乱码条目
- `⟦⟧` 占位符与源文本一一对应
- 行结构：表格行/列表项分行一一对应；句内折行合并允许

术语漂移扫描（glossary_drift 逻辑）：
- 统一术语的禁用变体表 + 英文术语残留检测
- ⚠️ 命中项必须对照英文原文逐条裁决后才修改——扫描器有系统性误报类：
  - 合法词包含禁用子串（如"验船师"含"验船"）
  - 源文本本就不同的概念（test load 试验载荷 ≠ proof load 验证载荷）
  - 实体标记按约定保留英文

## 二、成品 QA（PDF 出口）

`scripts/qa_scan.py <out.pdf> [--src src.pdf]`：
- 文字越界右缘（x > 版心+容差；排除竖排水印带）
- `⟦⟧` 占位符残留（必须为 0）
- 微字：CJK（含标点 `\u3000-\u303f`）字号 < 4.5pt（必须为 0）
- 页脚页码：逐页核对"第 N 页"连续（原版无页脚的页按约定豁免）
- 叠印：不同文本 span 相交（伪粗体同文双绘豁免）

`scripts/tables_coverage.py <src.pdf> <out.pdf>`：
- 源表格含源语言文字的单元格，输出同位置（±7pt）必须检出目标语言
- 缺失率 ≤5% 可接受（剩余通常为按约定保留的标准代号，需逐条裁决确认）

残留源语言扫描：白名单 = 内部水印、机构地址、标准号/牌号、公式、约定保留的实体标记。

## 三、视觉验收闭环

1. 渲染抽样 10–12 页/份：封面（免责声明）、目录、修订表、正文、大表、公式页、矩阵/旋转表头、附录算例、历史修订表、此前失败页
2. 视觉裁决：渲染样张交由子代理或由主控自行逐页审阅，判定标准：
   - 无乱码/叠印/裁切丢字；文字在栏框内、竖线不穿字
   - 表格行对齐 ±数像素可接受；字号 ≥4.5pt 可辨
   - 数值/公式与英文原版逐格一致
   - 免责声明框完整、页脚连续
3. fail 项 → 精确定位缺陷块（提取输出 PDF 对应位置 span 的 size/bbox 反查）→ **定点外科修复**（改具体块的译文/bbox/拆分关系；禁止大面积启发式改动——曾因通用合并策略把正确单元格内容并错栏位）→ 重建 → 复验
4. 全部 pass → 垃圾回收（garbage=4）+ 完整性校验 + 交付

## 四、构建摘要报告（交付附件）

每份文档一行：页数 | 译文条目 | QA 各项计数 | 视觉验收结果 | 修复记录 | 输出路径。
