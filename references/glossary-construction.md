# 领域词汇表自动构建协议 v2

没有现成词汇表时的标准作业程序。目标：产出三层结构的 `glossary.md`，使任何子代理都能做出与领域专家一致的术语决策。**词库是跨项目资产**：按行业沉淀、复用、增量修订。

## 1. 行业推断与确认（先于一切术语工作）

**从源文件推断行业**，按证据强度排序：
1. **引用的标准号**（最强信号）：GB/JB/NB → 中国承压/机械；ISO/IEC/IEEE → 国际电工/信息；ASME/API/ASTM → 美国机械/石油；EN/DIN → 欧洲；JIS → 日本。统计引用频次即可定位行业与国别体系。
2. 封面/扉页的机构名与丛书名（如 "ASME Boiler and Pressure Vessel Code" 直接给出行业+细分）。
3. 高频大写缩写聚类（如 MDMT/PWHT/NDE 聚集 → 承压设备制造）。
4. 章节标题关键词聚类（设计/材料/焊接/检验 → 制造业工程类）。
5. 图表类型（许用应力表/疲劳曲线 → 结构强度类）。

**判定输出**：主行业 + 子领域 + 相邻领域（如"承压设备制造 → 锅炉管道/焊接/材料/无损检测"）+ 国别标准体系。

**不确定即问，禁止猜测**：出现以下任一情况，必须向用户确认后才能定稿词库（AskUserQuestion 或启动确认环节一次性问清）：
- 两个候选行业并存且证据相当；
- 推断的行业与用户描述的任务背景不符；
- 源文件为跨行业合集（各分册行业不同，如合订本内含多个 Division/Part 体系切换）；
- 行业明确但**目标读者口未定**（工程参考 vs 学术出版 vs 合规用途，影响术语正式度与语气词严格度）。
多领域混合文档按章节登记各自领域，分别套用对应词库分区。

## 2. 全局词库资产（跨项目复用）

- 词库按行业沉淀在 `.work/glossary-library/<行业slug>.md`（项目工作区内，可随项目归档），结构同 glossary.md 的三层。
- **同行业二次项目：先查库、做减法**——复用既有词条，仅增量挖掘新术语与修订冲突项，查证工作量减 60% 以上。
- 项目完工后将 `terms.log` 高频条目回灌行业库，持续增值。
- 跨行业库冲突（如同一个英文缩写在不同行业不同义）：库内按行业分区存放，禁止跨区覆盖。

## 3. 术语挖掘（候选生成）

| 来源 | 方法 |
|---|---|
| 缩写 | regex `\b[A-Z]{2,}[0-9]*\b` 过滤常见英文词；记录全文档首现位置 |
| 多词术语 | 2–4 gram 频率统计，剔除停用词组合；表格表头/图注加权 |
| 定义句式 | "X means / X refers to / X shall mean / X是指/所称的X" |
| 既有双语线索 | 源文档内括号注音、参考文献中的双语标准名 |
| 高频专名 | 组织名、产品名、地名（多进入 keep-original 层） |

每个候选记录：出现次数、出现分块、上下文样例 1 条。

## 4. 权威查证（WebSearch）

按优先级检索官方译法：
1. 标准组织/行业机构官方双语文件（ISO/IEC/IEEE/EN/GB/行标/行业权威团体的中文版或术语页）
2. 全国科学技术名词审定委员会（term.org.cn）审定名词
3. 该领域头部企业的官方中文文档/手册
4. 权威百科与学术数据库的通用译法（多来源交叉验证）
5. 都没有 → 标记 `translator-decided`，由资深译者按构词法+领域惯例决策

每条记录：`英文 | 中文 | 来源URL/说明 | 置信层`。核心术语（预计全文高频出现的前 50 词）至少 70% 要有权威来源。

## 5. 分层定稿（glossary.md 结构）

```markdown
# 术语库（<行业> / <标准体系>）
> 适用文档：...；分层规则：verified=强制照用；consistent=全文统一；keep-original=不译
## verified（有权威来源，强制）
| 英文 | 中文 | 来源 |
## consistent（自洽决策，全文强制统一）
| 英文 | 中文 | 决策理由 |
## keep-original（保留原文）
标准号、牌号、单位、代码、品牌、型号、公式符号、人名
## 语气与文体规范
shall=应 shall not=不应 should=宜 may=可 must=必须
数字/单位/标点全半角规则；中英文间空格规则
```

## 6. 翻译期动态维护

- `terms.log`：子代理每块追加 ≤5 条新决策（`中文=English`），后续块强制延续
- **多车道并行时按车道分写**（`_terms.log` / `_termsB.log`），收尾合并——并发追加同一文件曾靠运气未坏，规范上禁止
- 主控在波次间抽查各车道日志，冲突立即裁决并回改（已知案例：多车道并行时同一术语曾出现异译，由收尾裁决统一）
- 全文完成后将 terms.log 高频条目回灌 glossary.md（资产沉淀，下次项目复用）

## 7. 快速通道

- 用户提供现成词汇表 → 合并为 verified 层，跳过查证
- 同领域二次项目 → 直接复用行业库（见 §2）
